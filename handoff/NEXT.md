## Что в 3.0, beta 2 (214)

- Приложение и расширение — каждое со своей библиотекой (`AppCore.xcframework` / `Libbox.xcframework`).
- **Серверы только для Xray**: сервер, который sing-box не понимает, хранится как outbound типа `xray`
  (его исходные outbounds Xray). sing-box ходит к нему через `socks` на 127.0.0.1:20800+i, Xray-core
  (`ptbridge.StartXray`) в расширении слушает эти порты (`tunnel-xray.json` в группе, пишет
  `LibraryStore.writeActiveConfig`). Приложение для пинга поднимает свой Xray на 30800+500·k.
  Сквозной тест в CI: Xray-сервер с маской `sudoku` ← наш Xray ← sing-box (`core/bridge/e2e_test.go`).
  Серверы появятся после обновления подписки.
- **Пинг**: серверы подключённой подписки — URL-тест через расширение без TCP-фильтра; остальные
  подписки (и всё без VPN) — ядро приложения; с VPN их задержка включает туннель. Первые 3 ошибки
  прогона пишутся в журнал словами ядра.
- **Догрузка серверов**: подписка в формате Xray JSON догружается обычным клиентом, недостающие
  серверы добавляются (`SubscriptionMerge`).
- **Журнал**: «Скопировать всё» (+ события расширения), без цветовых кодов; адреса серверов
  владельца и их IP скрываются (`Redactor.hideServers`); строки приложения не пропадают при
  переподключении ядра. Память расширения — в «Проверке соединения».
- **Панель «Серверы»**: меню удержания как в 1.5.0, «Выбрать несколько», «Ссылка, QR и JSON»,
  скруглённая подсветка, разгруженная прокрутка, свайп вниз после сворачивания.
- **Блокировка рекламы**: страница в настройках обоих стилей; Базовый / Стандартный (HaGeZi Light,
  по умолчанию) / Расширенный (HaGeZi Normal); DNS отвечает 0.0.0.0 / ::.
- Автопинг скрыт (`Prefs.autoPingAvailable = false`).

## 3.2.7 (262): пинг при kill switch напрямую до серверов; круглый отклик кнопок свайпа

Владелец (3.2.6): при включённом VPN нормально пингуется только сервер туннеля и серверы Xray-core, остальные —
«тайм-аут»/«обрыв», снова Reality/certificate; примерно с 3.2.3. В журнале: «1 через туннель, 67 ядром приложения»,
EOF и context deadline exceeded; память расширения в норме (21 МиБ) — дело не в памяти.
- Причина: с kill switch (includeAllNetworks) ядро приложения не может выйти мимо туннеля, а после PT-06 в туннеле
  нет правил для адресов серверов, поэтому каждая проверка шла цепочкой ЧЕРЕЗ подключённый сервер (США → Эстония).
  Hysteria2/UDP через VLESS Vision не проходят (Xray отвергает UDP/443 под Vision) → тайм-аут; сервер провайдера
  не пускает к другим его узлам → EOF, Reality, certificate. Без kill switch ядро привязано к en0 — там всё работало
  (вероятно, kill switch у владельца включён недавно; 3.2.3 его впервые пишет в журнал).
- Исправление (`ProbeExit`): расширение при kill switch слушает socks на 127.0.0.1 со случайными логином/паролем
  (`Prefs.probeExit`, ключ `pt.net.probeExit`, создаются один раз); правило `inbound: probe-in → direct` первым.
  Ядро приложения в `ConfigBuilder.probe(…, exit:)` ведёт каждый сервер и резолверы `dns-direct` через этот выход
  (`detour: probe-exit`). Дыры для чужого трафика нет: других правил direct не добавлено (PT-06 закрыт).
  Расширение убирает выход без kill switch (`ConfigBuilder.probeExit(in:keep:)`) и, если порт занят, запускается без
  него (строка в журнале). Приложение перед пингом проверяет, что порт слушает (`ProbeExitCheck`): у туннеля,
  запущенного старой сборкой, выхода нет — пинг идёт по-старому, журнал просит переподключить VPN.
  Серверы Xray-core в приложении по-прежнему через туннель (у владельца отвечают).

## Что в 3.0, beta 2 (214)

- Приложение и расширение — каждое со своей библиотекой (`AppCore.xcframework` / `Libbox.xcframework`).
- **Серверы только для Xray**: сервер, который sing-box не понимает, хранится как outbound типа `xray`
  (его исходные outbounds Xray). sing-box ходит к нему через `socks` на 127.0.0.1:20800+i, Xray-core
  (`ptbridge.StartXray`) в расширении слушает эти порты (`tunnel-xray.json` в группе, пишет
  `LibraryStore.writeActiveConfig`). Приложение для пинга поднимает свой Xray на 30800+500·k.
  Сквозной тест в CI: Xray-сервер с маской `sudoku` ← наш Xray ← sing-box (`core/bridge/e2e_test.go`).
  Серверы появятся после обновления подписки.
- **Пинг**: серверы подключённой подписки — URL-тест через расширение без TCP-фильтра; остальные
  подписки (и всё без VPN) — ядро приложения; с VPN их задержка включает туннель. Первые 3 ошибки
  прогона пишутся в журнал словами ядра.
- **Догрузка серверов**: подписка в формате Xray JSON догружается обычным клиентом, недостающие
  серверы добавляются (`SubscriptionMerge`).
- **Журнал**: «Скопировать всё» (+ события расширения), без цветовых кодов; адреса серверов
  владельца и их IP скрываются (`Redactor.hideServers`); строки приложения не пропадают при
  переподключении ядра. Память расширения — в «Проверке соединения».
- **Панель «Серверы»**: меню удержания как в 1.5.0, «Выбрать несколько», «Ссылка, QR и JSON»,
  скруглённая подсветка, разгруженная прокрутка, свайп вниз после сворачивания.
- **Блокировка рекламы**: страница в настройках обоих стилей; Базовый / Стандартный (HaGeZi Light,
  по умолчанию) / Расширенный (HaGeZi Normal); DNS отвечает 0.0.0.0 / ::.
- Автопинг скрыт (`Prefs.autoPingAvailable = false`).
